# Meeting Room Booking

REST API สำหรับจองห้องประชุมภายในองค์กรเดียว เขียนด้วย Go + SQLite

- จอง/แก้ไข/ยกเลิกห้อง โดยห้ามจองซ้อนเวลาในห้องเดียวกัน
- ดูตารางของห้องรายวัน และค้นหาห้องว่างที่จุคนได้
- มีหน้าเว็บให้ใช้ที่ `/` (ดู [หน้าเว็บ](#หน้าเว็บ)) แต่ไม่มีล็อกอินใน MVP (ดู [ข้อจำกัด](#ข้อจำกัด))

เอกสารออกแบบ: [context.md](context.md) (ศัพท์และขอบเขต), [design.md](design.md) (กฎ, API, data model), [task.md](task.md) (งานที่ทำ)

## เริ่มใช้งาน

ต้องมี Go 1.27+ (ไม่ต้องมี C compiler)

```bash
go run ./cmd/server
```

| Flag | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `-addr` | `:8080` | ที่อยู่ที่ฟัง |
| `-db` | `meeting-room.db` | ไฟล์ SQLite (สร้างให้เองถ้ายังไม่มี) |
| `-rooms` | `rooms.json` | ไฟล์ห้อง โหลดทุกครั้งที่เริ่ม (upsert ตาม `id`) |

เพิ่มหรือแก้ห้องโดยแก้ [rooms.json](rooms.json) แล้วเริ่มเซิร์ฟเวอร์ใหม่:

```json
[{"id": "r1", "name": "Alpha", "capacity": 8, "floor": 1}]
```

### รันด้วย Docker

```bash
docker build -t meeting-room .
docker run -p 8080:8080 -v meeting-room-data:/data meeting-room
```

- ฐานข้อมูลอยู่ที่ `/data` ต้อง mount volume ไม่งั้นข้อมูลหายเมื่อลบ container
- ห้องอ่านจาก `/app/rooms.json` ในอิมเมจ แก้ห้องโดย mount ไฟล์ของคุณทับ: `-v ./rooms.json:/app/rooms.json:ro`
- ตัวอิมเมจรันเป็นผู้ใช้ที่ไม่ใช่ root และมี flag ตั้งไว้แล้ว (`-addr :8080`, `-db /data/meeting-room.db`)

## หน้าเว็บ

เริ่มเซิร์ฟเวอร์แล้วเปิด http://localhost:8080 (ไม่ต้องติดตั้งหรือ build อะไรเพิ่ม ไฟล์หน้าเว็บอยู่ใน [web/](web/) และฝังไปกับไบนารี)

1. กรอก **ชื่อของคุณ** มุมบนขวา (จำไว้ในเบราว์เซอร์ ใช้เป็นผู้จองและใช้ยกเลิกการจองของตัวเอง)
2. **ค้นหาห้องว่าง:** เลือกวันที่ เวลาเริ่ม ระยะเวลา และจำนวนคน แล้วกด "ค้นหา" จะเห็นเฉพาะห้องที่ว่างและจุคนได้
3. กด **"จองห้องนี้"** ที่ห้องที่ต้องการ ถ้ามีคนจองตัดหน้าจะขึ้นข้อความแจ้งและรีเฟรชรายการให้
4. **ตารางห้อง:** เลือกห้องและวันที่เพื่อดูการจองทั้งหมด การจองของคุณที่ยังไม่เริ่มจะมีปุ่ม "ยกเลิก"

ช่วงเวลาเลือกได้เฉพาะที่จองได้จริง (ครั้งละ 30 นาที 08:00–20:00 วันจันทร์–ศุกร์) และแสดงเวลา Asia/Bangkok ชื่อผู้ใช้ไม่ได้ผ่านการยืนยันตัวตน ใครก็กรอกชื่อใครก็ได้

## กฎการจอง

- ช่วงละ 30 นาที ขั้นต่ำ 30 นาที สูงสุด 4 ชั่วโมง เริ่ม/จบที่ :00 หรือ :30
- จองได้ 08:00–20:00 (Asia/Bangkok) จันทร์–ศุกร์ ภายในวันเดียว
- จองย้อนหลังไม่ได้ และล่วงหน้าได้ไม่เกิน 60 วัน
- จำนวนผู้เข้าร่วมต้องไม่เกินความจุห้อง
- จบ 10:00 กับเริ่ม 10:00 ในห้องเดียวกันไม่ถือว่าชน
- ยกเลิกหรือแก้ไขได้เฉพาะผู้จอง และก่อนเวลาเริ่มเท่านั้น แก้ได้ `start`, `end`, `attendees` (เปลี่ยนห้องไม่ได้ ให้ยกเลิกแล้วจองใหม่) ผลที่แก้แล้วต้องผ่านกฎเดียวกับการจอง

## API

เวลาเป็น RFC 3339 (ส่ง offset ใดก็ได้ ตอบกลับเป็น UTC)

| Endpoint | หน้าที่ |
|---|---|
| `GET /rooms` | รายการห้อง |
| `GET /rooms/available?start=&end=&attendees=` | ห้องที่ว่างตลอดช่วงและจุคนได้ |
| `GET /rooms/{id}/bookings?date=YYYY-MM-DD` | การจองของห้องในวันนั้น (ตามเวลา Bangkok) |
| `POST /bookings` | จอง body: `room_id, user_id, start, end, attendees` → 201 |
| `POST /bookings/{id}/cancel` | ยกเลิก ส่ง header `X-User-Id` → 200 |
| `PATCH /bookings/{id}` | แก้ไข/ย้ายเวลา ส่ง header `X-User-Id` และ body อย่างน้อยหนึ่งใน `start, end, attendees` (ฟิลด์ที่ไม่ส่งคงเดิม) → 200 พร้อม Booking ที่อัปเดต |

```bash
# จอง
curl -X POST localhost:8080/bookings -d '{
  "room_id": "r1", "user_id": "alice",
  "start": "2026-11-17T10:00:00+07:00", "end": "2026-11-17T11:00:00+07:00",
  "attendees": 4}'

# แก้ไข/ย้ายเวลา (ส่งเฉพาะฟิลด์ที่เปลี่ยน)
curl -X PATCH localhost:8080/bookings/<id> -H 'X-User-Id: alice' -d '{
  "start": "2026-11-17T13:00:00+07:00", "end": "2026-11-17T14:30:00+07:00"}'

# ยกเลิก
curl -X POST localhost:8080/bookings/<id>/cancel -H 'X-User-Id: alice'
```

### ข้อผิดพลาด

รูปแบบ `{"code": "...", "message": "..."}`

| HTTP | code |
|---|---|
| 422 | `invalid_slot`, `invalid_duration`, `outside_business_hours`, `in_the_past`, `too_far_ahead`, `over_capacity`, `invalid_request` |
| 409 | `time_conflict`, `already_cancelled`, `already_started` (ใช้กับแก้ไขด้วย) |
| 403 | `not_booker` |
| 404 | `room_not_found`, `booking_not_found` |

## ข้อจำกัด

- **ไม่มีล็อกอิน:** ระบบเชื่อ `user_id` ที่ผู้เรียกส่งมา ใช้หลังเครือข่ายองค์กรที่เชื่อถือได้เท่านั้น
- ไม่เช็กวันหยุดนักขัตฤกษ์
- รันโปรเซสเดียว การกันจองซ้อนอาศัย transaction ของ SQLite ถ้าจะรันหลายโปรเซสต้องย้ายฐานข้อมูล
